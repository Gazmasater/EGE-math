# Исходные архивы ОГЭ по информатике

На 18.10.2026 получены и проверены **371/371** оригинальных архива, недостающих **0**. Бинарные данные передаются частями через Releases этого репозитория; Git содержит реестр, контрольные суммы и скрипт восстановления. Git LFS не используется. Рабочая копия архивов занимает 14 833 464 306 байт (около 13,82 ГиБ), уникальные байты — 311 858 950 байт в 147 разных архивах.

`tasks.json` — неизменённый реестр 371 задачи с полями `id`, `sourceId`, `group`, `text`, `urls`. Связи с архивами сверяются с 16 первичными `oge-informatics-*.raw.html` через существующий `readOgeCatalog`. Группы: поиск текста — 66, поиск файлов — 160, презентации — 59, электронные таблицы — 86.

Оригинальные байты восстанавливаются по исходным путям `fipi-assets/oge-informatics/docs/...`. ZIP/RAR не перепаковываются: части последовательно соединяются, после чего проверяется SHA-256 оригинала. Одинаковые архивы скачиваются один раз и копируются во все соответствующие пути задач. Поэтому размер рабочей копии значительно превышает объём скачивания. Загруженные архивы исключены из Git через `.gitignore`.

## Реестры и проверки

- `manifest.json`: покрытие, ID задач, исходный URL, фактический источник, время получения, HTTP/TLS, попытки, путь, размер, SHA-256 и результаты проверки каждого полученного архива.
- `missing.json`: только неполученные/непрошедшие проверку архивы с причинами и попытками. Пустой массив означает полное покрытие.
- `registry-validation.json`: сверка всех пяти полей `tasks.json` с первичными HTML и SHA-256 всех 16 страниц.
- `validation/<sha256>.json`: сигнатура формата, результат полного `7z t`, число файлов/каталогов, распакованный объём, перечень всех членов с размерами и CRC. Проверка включает распаковку всех членов, контрольные суммы и отсутствие шифрования. Она подтверждает читаемость байтов файлов, но не является решением задач или визуальной оценкой документов.
- `document-validation.json`: дополнительная проверка всех вложенных ODS/ODT в различающихся архивах. Документы извлекаются в память без изменения байтов; проверяются внутренние CRC, MIME, структура ODF и синтаксис каждой XML-части. Сохранены SHA-256 самих документов.
- `release.json`: точный порядок частей каждого оригинала, их URL в Releases этого же репозитория, размеры и SHA-256. `actualSource` в основном manifest обозначает источник оригинала ФИПИ; способ последующего получения копии указан отдельно в `storage` и `releaseManifest`.

- `release-validation.json`: независимое скачивание всех 707 частей из публичного Release в чистом GitHub Actions, сборка всех 147 оригиналов и проверка их размеров/SHA-256; ссылка на запуск и SHA-256 реестра частей. Дополнительно сверены серверные SHA-256 всех assets.

Только успешный HTTP-ответ с настоящей сигнатурой ZIP/RAR и полной проверкой содержимого считается получением файла. HTML-ошибки, пустые, обрезанные, зашифрованные и повреждённые архивы отклоняются. Похожий текст задачи, имя файла или размер не являются доказательством тождества архивов. Сторонние неподтверждённые копии не включаются в покрытие.

## Получение и воспроизведение

После обновления репозитория запустите восстановление (Python 3.11+, без дополнительных пакетов):

```sh
git pull --ff-only origin main
python scripts/restore-oge-informatics-archives.py
```

Скрипт делает три параллельных запроса, максимум три попытки на часть, проверяет HTTPS, размеры и SHA-256 частей и собранных архивов. Повторный запуск использует только проверенный кеш в `storage/oge-informatics-release/`. Для скачивания и проверки без копирования во все 371 пути: `python scripts/restore-oge-informatics-archives.py --cache-only`. При необходимости задайте `HTTPS_PROXY`; учётная запись GitHub для публичного Release не нужна. Для рабочей копии, кеша и временных файлов требуется около 16 ГБ свободного места.

Локальная проверка: Python 3.11+, Node.js и 7-Zip с поддержкой RAR (`7zz`/`7z` в PATH; в Windows также распознаётся `C:/Program Files/7-Zip/7z.exe`). Путь можно задать переменной `SEVEN_ZIP`.

```sh
node scripts/audit-oge-informatics-archive-registry.js
python scripts/download-oge-informatics-archives.py --verify
python scripts/audit-oge-informatics-archive-documents.py
python scripts/test-oge-informatics-archives.py
```

`--verify` не обращается к сети и не изменяет данные: проверяет каждый локальный размер и SHA-256, состав manifest/missing и заново полностью распаковывает для проверки каждый различающийся набор байтов через `7z t`. Совпадающие хеши используют одно свидетельство проверки; каждая копия файла отдельно хешируется.

Для повторного сбора с официального источника дополнительно нужен `curl` с доверенным TLS:

```sh
python scripts/download-oge-informatics-archives.py --workers 3 --attempts 3
python scripts/audit-oge-informatics-archive-documents.py --write-report
```

Одновременно выполняются три загрузки, максимум три попытки на URL, тайм-аут соединения 15 секунд, запроса 300 секунд. Проверенные результаты промежуточного запуска сохраняются в игнорируемом `storage/oge-informatics-archives/results/`; повторный сбор использует их только после проверки локального SHA-256. Manifest и missing обновляются по завершении сбора. Первичные HTML, задачи, решения и SQLite скрипт не изменяет.
