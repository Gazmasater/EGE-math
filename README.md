# EGE Math

Локальный каталог заданий ЕГЭ и ОГЭ по математике и физике, ОГЭ по информатике из открытого банка ФИПИ.

## Запуск

Требуется Node.js с встроенным модулем `node:sqlite`, например Node.js 24.

```powershell
node server.js
```

После запуска откройте <http://localhost:8765>.

Главная страница содержит полный банк профильной математики: все доступные в ФИПИ разделы и темы КЭС, задания с кратким и развёрнутым ответом. Страница `/math` ведёт в обзор математических разделов. Отдельно сохранены подборки второй части: уравнения, стереометрия, неравенства, финансовая математика, оптимальный выбор, планиметрия, задачи с параметром и числа и их свойства.

В текущем снимке математического банка 1148 уникальных заданий: 673 с кратким ответом и 475 с развёрнутым. Обновить задания и изображения можно командой:

```powershell
npm run fetch:math
```

Проверить количество заданий, оба типа ответа, последовательность страниц и наличие локальных изображений:

```powershell
npm run audit:math-catalog
```

Раздел `/physics` содержит полный банк физики — 2344 уникальных задания: 1291 с кратким ответом, 538 с развёрнутым, 348 с выбором нескольких ответов, 166 на установление соответствия и 1 с выбором одного ответа. Задачи распределены по четырём разделам и 16 крупным темам КЭС; нужная подборка открывается параметром `topic`, например `/physics?topic=1.2` для динамики. Обновить задания и изображения можно командой:

```powershell
npm run fetch:physics
```

Проверить страницы, уникальность заданий, все форматы ответа, классификацию КЭС и локальные ресурсы:

```powershell
npm run audit:physics-catalog
```

Условия и связанные ресурсы сохранены локально. Подключение к ФИПИ требуется только при использовании кнопки обновления.

## ОГЭ по математике

Раздел `/oge` содержит полный снимок [открытого банка ФИПИ](https://oge.fipi.ru/bank/index.php?proj=DE0E276E497AB3784C3FC4CC20248DC0): 3884 задания и 2888 связанных файлов на 07.10.2026. Доступны восемь разделов и все темы КЭС, поиск по номеру и условию, отдельные страницы `/tasks/{ID}` и переходы между заданиями. Задания без метки КЭС находятся в отдельной подборке. В 359 практических заданиях (`/oge?topic=practical`) общее условие и рисунки сохранены у каждого вопроса, в том числе без JavaScript.

Каталог показывает по 12 условий на странице, в том числе без JavaScript. Например: `/oge?topic=7.2` — треугольники, `/oge?topic=7.2&page=2` — следующая страница, `/oge?topic=all` — весь банк. Классификация следует меткам ФИПИ; номера заданий в экзаменационном варианте автоматически не назначаются.

```powershell
npm run fetch:oge
npm run audit:oge
npm run test:oge
```

Для запущенного предпросмотра на `127.0.0.1:8877`: `npm run audit:oge:pages` проверяет все страницы и состав подборок, условия задач, прежние URL и sitemap; `npm run check:oge:pages` проверяет настольное и мобильное отображение, поиск, переходы и рисунки без JavaScript. Адрес задаётся `OGE_SITE_ORIGIN`, путь к Chrome — `CHROME_BIN`.

Импорт проверяет полноту банка и уникальность идентификаторов до замены выгрузки. Рисунки ОГЭ хранятся отдельно в `fipi-assets/oge`, чтобы ресурсы разных банков не подменяли друг друга. Исходные выгрузки и ресурсы помечены в `.gitattributes` как двоичные снимки: Git сохраняет их байты и кодировку ФИПИ без преобразования переводов строк. Кнопка обновления внутри ОГЭ обновляет этот банк.

Ответы и решения ОГЭ публикуются через существующий `/admin` после проверки. Сам импорт условий не создаёт решений и не копирует тексты «Решу ОГЭ». Для изолированной проверки можно задать `EGE_SOLUTIONS_DB` — путь к отдельной SQLite; рабочая база по умолчанию остаётся `storage/solutions.sqlite`.

## ОГЭ по физике

Раздел `/oge-physics` содержит полный снимок [открытого банка ФИПИ по физике ОГЭ](https://oge.fipi.ru/bank/index.php?proj=B24AFED7DE6AB5BC461219556CCA4F9B): 1506 заданий, 16 исходных страниц и 821 связанный файл на 07.10.2026. Доступны четыре раздела и все 83 подтемы КЭС ФИПИ, шесть форматов ответа (включая расстановку терминов), поиск, серверная пагинация по 12 заданий и отдельные страницы задач. В 63 вопросах сохранено общее условие вместе с рисунками; всё доступно без JavaScript. Например: `/oge-physics?topic=1.12` — трение, `/oge-physics?topic=all` — весь банк.

Короткие номера ФИПИ не уникальны между предметами: номер `465498` есть и в математике, и в физике ОГЭ. Поэтому физические задачи имеют отдельные внутренние идентификаторы и URL `/tasks/OGEPHYS{номер}`, например `/tasks/OGEPHYS465498`. Исходный номер `465498` остаётся виден и находится через поиск внутри физики. При добавлении решения в `/admin` используется идентификатор из URL с префиксом `OGEPHYS`: он также разделяет API, комментарии и обратную связь. Прежние математические URL и решения не изменяются.

```powershell
npm run fetch:oge-physics
npm run audit:oge-physics
npm run test:oge
npm run audit:oge-physics:pages
npm run check:oge-physics:pages
```

Импортёр и проверки общие для банков ОГЭ, но исходные страницы, ресурсы (`fipi-assets/oge-physics`), темы, кэши и история добавлений изолированы. Кнопка обновления физики ОГЭ обновляет только этот банк. Решения не импортируются и не копируются с «Решу ОГЭ»; проверенные ответы и самостоятельные решения публикуются через существующую админку. Перед выкладкой сверяйте изменения с актуальной версией рабочего сайта.

## ОГЭ по информатике

Раздел `/oge-informatics` содержит 1585 заданий [банка ФИПИ по информатике ОГЭ](https://oge.fipi.ru/bank/index.php?proj=74676951F093A0754D74F2D6E7955F06), полученных 17.10.2026: 1053 с кратким ответом, 79 на последовательность и 453 с развёрнутым ответом. Доступны четыре раздела и все 25 подтем официального фильтра КЭС, поиск по номеру/условию и страницы по 12 заданий. Учебное распределение проверено по содержанию всех условий; исходные КЭС сохранены отдельно. Пустые темы отображаются с нулевыми счётчиками.

Добавлены 16 учебных групп, сопоставленных с [каталогом «Решу ОГЭ»](https://inf-oge.sdamgia.ru/prob_catalog), например `/oge-informatics?topic=type.9` — подсчёт путей, `type.16` — написание программы. Основные и дополнительные типы источника указаны явно: составление команд исполнителя соответствует Д13, хотя относится к тому же навыку, что основной тип 5. Это сопоставление семейств задач, а не подтверждение номера каждого задания в экзаменационном варианте или совпадения всех ответов. Переходы между отдельными задачами информатики сохраняют выбранный учебный тип. [Отчёт сверки](docs/audits/oge-informatics-types-2026-10-17/index.html) содержит распределение всех 1585 ID и источники для каждой группы.

Проверенное распределение хранится в `lib/oge-informatics-classification.json`: хеш условия не позволяет применять старую классификацию к изменённой задаче. У 483 задач уточнены темы, включая дополнительную тему кодирования у 79 задач об объёме текста. После обновления банка сначала повторяют содержательную сверку; `node scripts/build-oge-informatics-classification.js --write` сохраняет её результат, а `npm run audit:oge-informatics:types` проверяет его без изменений.

Условия и рисунки работают без JavaScript. В Git сохранены 16 исходных страниц и 812 ресурсов в `fipi-assets/oge-informatics`. Для 371 архива ZIP/RAR отображаются обычные ссылки «Скачать файл задания» на официальный сервер ФИПИ. Эти архивы могут занимать десятки мегабайт и повторяться у разных вопросов, поэтому они не копируются в репозиторий; для скачивания нужен доступ к ФИПИ. Проверка вложений использует HEAD и не скачивает архивы целиком.

Новые задачи имеют URL `/tasks/OGEINF{номер}` и отдельные ID решений, комментариев и обратной связи. Исходный короткий номер остаётся на карточке и находится поиском. Пример: `/oge-informatics?topic=all`, `/oge-informatics?topic=3.2&page=2`. Решения импортом не создаются; для их публикации используется `/admin` с ID из адреса страницы.

```powershell
npm run fetch:oge-informatics
npm run audit:oge-informatics
npm run audit:oge-informatics:attachments
npm run audit:oge-informatics:types
npm run test:oge-informatics:types
npm run test:oge
npm run audit:oge-informatics:pages
npm run check:oge-informatics:pages
```

Последние две команды используют запущенный предпросмотр на `127.0.0.1:8877`; адрес можно задать через `OGE_SITE_ORIGIN`. HTTP-аудит проверяет все темы и типы, страницы, условия, переходы между задачами одного типа и прежние URL. Браузерный аудит охватывает все непустые подтемы и 16 типов, форматы ответов, ZIP/RAR, поиск, навигацию и доступность вложений без JavaScript на 1280/390 px.

## Решения

Под каждой задачей есть кнопка «Решение». До публикации посетитель увидит сообщение, что решение ещё не готово. После публикации становятся доступны и ответ, и текст решения.

Решения добавляются через `/admin`: введите номер задания, заполните ответ и текст решения, затем отметьте «Опубликовать». Данные хранятся в локальной SQLite-базе `storage/solutions.sqlite` с журналом WAL; каталог исключён из Git.

## Личный кабинет и комментарии

Посетитель может зарегистрироваться через `/account/register`, указав ФИО, город, электронную почту и пароль. После входа комментарии доступны к опубликованным решениям: на самостоятельной странице задания и в окне «Решение» в каталоге. В личном кабинете `/account` отображаются профиль и собственные комментарии.

Почта используется только для входа и не выводится рядом с комментариями. Пароли сохраняются в SQLite только в виде хеша; для сессий используются защищённые HTTP-only cookie. Встроено ограничение частоты регистраций, попыток входа и отправки комментариев.

## Стереометрия: правила для схем

Перед публикацией решения по стереометрии схема проверяется вместе с условием и текстом решения.

- Под рисунком обязательна подпись с принадлежностью каждой добавленной точки ребру, грани или прямой и, при необходимости, отношением отрезков.
- Повторный аудит схем проводится по цепочке «условие → SVG → подпись → решение» для каждой опубликованной схемы, а не только по тексту подписи. У каждой точки из условия должна быть реальная позиция на соответствующем ребре, грани или окружности; подпись рядом с пустым местом не считается точкой.
- Для цилиндра обе точки одной образующей наносятся на одну вертикаль; для середины, центра тяжести и точки деления координата на SVG проверяется по определению, а не только по названию. Перед публикацией схемы просматриваются в отрисованном виде, включая мобильную ширину.
- Контур сечения указывается в порядке обхода (например, `M–P–K–N`). Внутренние и вспомогательные точки не включаются в контур.
- Каждая точка на SVG ставится на соответствующее ребро по координатам; нельзя заменять точку на соседнем или похожем ребре.
- Если рисунок показывает плоскость, её граница должна проходить через все вершины фактического сечения. Точки внутри плоскости отмечаются отдельно.
- Уравнение плоскости нельзя записывать без вывода: перед ним обязательно показываются направляющие векторы, развёрнутые скалярные произведения нормали с ними, систему для коэффициентов нормали с её решением и подстановку точки плоскости. Нельзя переходить к упрощённому уравнению системы без пояснения деления или умножения. При пересечении с ребром публикуется подстановка параметра и её решение.
- Не использовать векторное произведение: оно не входит в школьную программу ЕГЭ. Нормаль плоскости выводится из системы условий перпендикулярности её направляющим векторам; площади и расстояния считаются школьными формулами (основание и высота, теорема косинусов, скалярное произведение, координаты).
- Не использовать барицентрические координаты и коэффициенты. Принадлежность точки плоскости доказывается школьными векторами, параллельностью прямых, отношениями отрезков или обычными координатами с полным выводом.
- Перед публикацией сверяются: условие → решение → подпись → SVG, затем проверяются отрисовка SVG и публичный API решения.
- Для каждой задачи дополнительно сверяются условие, ответ и ключевые вычисления с «Решу ЕГЭ — профильная математика» (`https://math-ege.sdamgia.ru/`). При расхождении первичным источником остаётся открытый банк ФИПИ; решение не публикуется до ручной проверки.

## Постоянный контекст проекта

### Публичный сайт и решения

- Основной адрес: `https://ege-fipi.ru`. Старый адрес `http://176.126.99.27:8765` должен всегда перенаправлять на HTTPS-домен.
- Приложение работает как служба `ege-math` на `127.0.0.1:8766`; Nginx принимает публичный трафик.
- Для каждой актуальной задачи есть самостоятельная страница `/tasks/{ID}`. Она должна отдавать условие и, если решение опубликовано, ответ, текст решения и схему без выполнения JavaScript.
- Решения хранятся в SQLite обычным текстом. Не переводить их вручную в HTML в базе: безопасная математическая разметка строится при выводе серверной функцией `renderMathSolution`/`renderMathText`.
- Формулы в публичном выводе должны быть типографскими: вертикальные дроби, корни с надчёркиванием, степени и индексы, векторы. Математические элементы выравниваются по середине строки, чтобы числа, операции и формулы не смещались относительно друг друга.
- В тексте решений не использовать `/` для деления. Для новой дроби в исходнике применять запись `⟦числитель¦знаменатель⟧`: на странице она выводится вертикальной дробью.
- В записи `√14v` под корнем находится только `14`, а `v` — множитель. Для составного подкоренного выражения в тексте решения обязательны скобки: `√(14v)`. Это проверяется на всех опубликованных решениях после изменения форматирования.
- При изменении решения необходимо проверять обе точки показа: API `/api/solutions/{ID}` и страницу `/tasks/{ID}`.
- В разделах каталога пагинация выводится одновременно над списком и внизу; обе панели должны показывать одну страницу. При возврате из истории браузера и после изменения ширины окна разбиение пересчитывается, а интерфейс не должен оставаться скрытым.
- В базе могут оставаться архивные решения к заданиям, которых уже нет в текущей выгрузке ФИПИ. Не добавлять в sitemap и не отправлять на переобход URL без актуального условия.

### SEO

- Страницы разделов и задач имеют уникальные `title`, description, canonical, Open Graph, JSON-LD, `lang="ru"` и один H1.
- `robots.txt` разрешает публичный каталог и закрывает `/admin`, `/api/` и `/update`; `sitemap.xml` формируется динамически из актуальных заданий и опубликованных дат решений.
- Служебные маршруты дополнительно отдают `X-Robots-Tag: noindex, nofollow`; несуществующие адреса обязаны отвечать `404`, а не главной страницей.
- После масштабного изменения каталога проверять доступность всех URL из sitemap и обновлять sitemap в Яндекс.Вебмастере.

### Яндекс Вебмастер и Метрика

- Сайт подтверждён в Яндекс.Вебмастере; счётчик Метрики — `112561663`.
- Секреты Яндекса находятся только в `/root/.config/yandex-webmaster.env` и не попадают в Git или документацию.
- Автоматическая аналитика подключена профилем `/etc/yandex-site-report/ege-fipi.env`: ежедневный отчёт Вебмастера и еженедельная сводка Вебмастер+Метрика запускаются таймерами `yandex-site-report@ege-fipi.timer` и `yandex-site-weekly-summary@ege-fipi.timer`.
- Sitemap `https://ege-fipi.ru/sitemap.xml` зарегистрирован в Вебмастере. Для страниц с опубликованными решениями допускается отправка на переобход только после проверки, что их URL есть в актуальном sitemap.
