# Подключение Wordstat API для ege-fipi.ru

Инструкция сохранена 16 октября 2026 года. Для обновления анализа спроса по ОГЭ и ЕГЭ, математике и физике нужно настроить Wordstat в Yandex Search API и сохранить доступ на сервере проекта.

## Текущий доступ

Проверка 16 октября подтвердила, что сохранённый токен API Директа действителен: `Clients.get` в Direct v5 ответил HTTP 200. Старый метод Wordstat `GetWordstatReportList` с тем же токеном вернул ошибку 509 «Метод недоступен в данной версии API». Результат сохранён в [direct-token-check.json](seo/wordstat-2026-10-16/direct-token-check.json).

[Официальная справка Wordstat](https://yandex.ru/support2/wordstat/ru/content/api-wordstat) направляет в Wordstat API сервиса Yandex Search API. Для продолжения нужны новый API-ключ и идентификатор каталога `folderId`. Подключение нового доступа пока не подтверждено.

## Создание доступа

1. Откройте [Yandex AI Studio](https://aistudio.yandex.cloud/) и войдите через Яндекс ID. При первом входе создайте организацию и облако; каталог `default` появится автоматически. Если облако и каталог уже есть, используйте их.
2. Нажмите **«Привязать платёжный аккаунт»**. Выберите существующий или создайте новый. Для работы API нужен платёжный аккаунт со статусом `ACTIVE` или `TRIAL_ACTIVE`. [Начало работы с Search API](https://aistudio.yandex.ru/ru/docs/search-api/quickstart/).
3. Справа сверху нажмите **«Создать API-ключ»**. Укажите описание, например `ege-wordstat`, выберите срок действия и нажмите **«Создать»**. Сохраните секретное значение ключа: после закрытия диалога оно больше не показывается. При таком способе создания сервисный аккаунт и права для Search API создаются автоматически. [Инструкция по созданию ключа](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/get-api-key).
4. Скопируйте **`folderId` — идентификатор каталога**, в котором создан ключ. Вверху интерфейса AI Studio наведите указатель на название каталога и нажмите значок копирования. [Инструкция Wordstat GetTop](https://aistudio.yandex.ru/ru/docs/search-api/operations/wordstat-gettop).

Для вручную настроенного сервисного аккаунта требуются роль `search-api.webSearch.user` на каталоге и область действия API-ключа `yc.search-api.execute`.

## Сохранение на сервере

Файл настроек: `/root/.config/yandex-search.env`. Сохраните в нём две строки, заменив заполнители своими значениями:

```dotenv
YANDEX_SEARCH_API_KEY=секретное_значение_ключа
YANDEX_SEARCH_FOLDER_ID=идентификатор_каталога
```

В `YANDEX_SEARCH_API_KEY` должно быть секретное значение, а не идентификатор ключа. Установите права доступа к файлу `600`:

```bash
chmod 600 /root/.config/yandex-search.env
```

Секретное значение не нужно отправлять в чат или добавлять в репозиторий. После сохранения сообщите «сохранил» либо укажите путь к файлу, если выбрано другое расположение.

## Стоимость

По тарифу, проверенному 16 октября 2026 года, Wordstat GetTop и GetDynamics стоят **20 ₽ за 1 000 API-запросов с НДС**. Например, 500 обращений к этим методам стоят 10 ₽. Распределение по регионам GetRegionsDistribution стоит 50 ₽ за 1 000 запросов; получение дерева регионов GetRegionsTree не тарифицируется. Перед новой массовой выгрузкой сверяйте [актуальный тариф](https://aistudio.yandex.ru/ru/docs/search-api/pricing).

## Продолжение анализа

После сохранения доступа проверить авторизацию одним запросом Wordstat GetTop, затем обновить частотности по четырём направлениям: ОГЭ математика, ЕГЭ математика, ОГЭ физика и ЕГЭ физика. Использовать Россию (`regions: ["225"]`), все устройства (`devices: ["DEVICE_ALL"]`), отдельно измерять широкие запросы и запросы в кавычках.

Документированный адрес GetTop: `https://searchapi.api.cloud.yandex.net/v2/wordstat/topRequests`. Имена переменных выше — выбранные имена локальной конфигурации проекта; клиент нового API ещё предстоит подключить к этому файлу.

Текущий [отчёт по спросу](seo/wordstat-2026-10-16/report.html) содержит сохранённые частотности от **8 октября 2026 UTC**. Свежая выгрузка 16 октября не получена. При обновлении сохранить дату, параметры и исходные ответы нового API, не суммировать пересекающиеся частоты и не представлять их как прогноз посещаемости.
