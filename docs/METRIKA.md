# Метрика ege-fipi.ru

Счётчик: [112561663](https://metrika.yandex.ru/dashboard?id=112561663). Первоначальная настройка от 24.09.2026; навигация каталогов обновлена 06.10.2026.
Фактические цели и API-сегменты сохранены в `metrika-config.json`. Автоматические цели и настройки фильтрации роботов сохранены.

| Цель | Идентификатор | ID | Когда срабатывает |
|---|---|---:|---|
| Просмотр решения | `solution_open` | 663176353 | Окно с успешно загруженным решением открыто; либо заголовок готового решения на странице задания виден минимум на 50% в течение секунды в активной вкладке |
| Переход к следующему заданию | `next_task` | 663176354 | Нажата ссылка следующего задания или пользователь перешёл вперёд по страницам каталога |
| Успешная регистрация | `registration_success` | 663176387 | Сервер создал аккаунт и браузер получил страницу после перенаправления |

Параметр `placement` различает окно (`dialog`), страницу задания (`task_page`) и каталог (`catalogue`). Повторное намеренное открытие окна считается новым действием. Статическое решение учитывается один раз за загрузку страницы; само наличие HTML решения не считается просмотром. `next_task` в каталоге с 06.10.2026 означает переход к следующему заданию текущей подборки (или текущей выборки поиска). Перелистывание использует `placement=catalogue`, кнопка после решения — `placement=catalogue_dialog`. У одного действия одно событие, в том числе при загрузке следующей серверной порции. Ранее одна страница могла содержать несколько заданий; учитывать изменение семантики при сравнении периодов. Начальная загрузка, переход по старому якорю, адаптация экрана и возврат назад цель не отправляют. Цель перехода по ссылке измеряет намерение перейти; загрузку следующего документа она не подтверждает. С 06.10.2026 каталог загружает новый HTML-документ каждые 12 заданий, поэтому просмотры и глубина также не полностью сопоставимы с прежней клиентской пагинацией.

Регистрация передаётся через отдельный случайный cookie-маркер со сроком 120 секунд: сервер устанавливает его только после успешного INSERT; браузер удаляет перед отправкой события. ФИО, email, пароль, ID аккаунта не передаются. Обновление страницы не повторяет событие. Ошибки формы, занятый email и обычный вход не создают маркер. Блокировщики аналитики могут препятствовать доставке событий; успешная регистрация от них не зависит.

На страницах заданий навигация продублирована после решения, а в окне решения добавлена ссылка на следующее задание из того же раздела. Ожидание обратного вызова Метрики при обычном переходе ограничено 250 мс.

## Отчёты

Через официальный Management API созданы три API-сегмента. Они сохранены на стороне Метрики; это не пользовательские отчёты в избранном веб-интерфейса.

| Сегмент | ID | Условия |
|---|---:|---|
| Поиск без роботов и технических визитов | 1008108503 | Органический поиск; исключены распознанные роботы, HeadlessChrome и явно отмеченные технические визиты |
| Мобильный поиск | 1008108504 | Предыдущий сегмент, только смартфоны |
| Роботы и технические визиты | 1008108505 | Распознанные роботы либо HeadlessChrome либо явная техническая метка |

Точные выражения находятся в `scripts/metrika-report.py` и `metrika-config.json`. Технический сегмент не означает, что все визиты принадлежат владельцу. Старые посещения обычным браузером без явной метки нельзя достоверно отнести к владельцу.

Новые визиты получают параметр `traffic_kind=public` или `technical`; автоматический браузер определяется по `navigator.webdriver`/HeadlessChrome. Для собственных проверок открыть `https://ege-fipi.ru/?analytics_technical=1` в используемом браузере: настройка сохранится локально. Отключение — `?analytics_technical=0`. Управляющий параметр удаляется из адреса до инициализации счётчика. При запрещённом localStorage сохранение настройки между страницами недоступно.

Выгрузка трёх отчётов без изменения счётчика:

```sh
python3 scripts/metrika-report.py --out /tmp/ege-metrika-report
python3 scripts/metrika-report.py --date1 2026-09-25 --date2 2026-10-01 --out /tmp/ege-metrika-first-week
```

По умолчанию берутся семь завершённых дней по Москве. Результат: `REPORT.md`, `summary.json` и три исходных JSON. OAuth читается из `YANDEX_METRIKA_TOKEN` либо защищённого `/root/.config/yandex-webmaster.env`; токен не сохраняется в отчёты.

Итоги запрашиваются без группировки по дням: из-за privacy-фильтрации Метрика может скрывать небольшие дневные строки даже без сэмплирования. В контрольном периоде 14–23 сентября полный поисковый итог — 146 визитов, но с дневной группировкой видны только 119. Это ограничение детализации, а не потеря трафика. Флаги API сохраняются в JSON.

Первое полное окно после внедрения — 25 сентября – 1 октября; оценить 2 октября. Сравнивать долю визитов с просмотром решения, переходом дальше и регистрацией, отдельно по мобильному поиску. Данных новых целей за прошлые даты нет. Изменение отказов после добавления целей само по себе не доказывает улучшения сайта.

## Проверки

`npm run test:analytics` проверяет повторную инициализацию, потребление регистрационного маркера, техническую метку и работу при заблокированном хранилище/счётчике.

`TMPDIR=/dev/shm npm run check:analytics:pages` использует отдельный сервер на `http://127.0.0.1:8876` с копией SQLite. Требуется Chrome. Все запросы к Метрике, Cloudflare и рекламному SDK блокируются; события проверяются локальной заглушкой. Только на этом адресе выполняется регистрация тестового аккаунта. Для опубликованного сайта использовать `ANALYTICS_ORIGIN=https://ege-fipi.ru`; создание аккаунтов тогда пропускается. Сервер предпросмотра должен работать с отдельной копией базы, никогда с рабочей базой сайта.

Проверены 360, 390 и 1280 px, обе предметные области, решения и соседние задания, отсутствие горизонтального переполнения/битых изображений/ошибок JS, регистрация с ошибкой, успешная регистрация, повторный email, обновление страницы и вход. Снимки просмотрены визуально. Записи реальных сессий Вебвизора не просматривались: подключение для воспроизведения недоступно; наличие доступа к Reporting API этого не заменяет.

Регрессия новой навигации: `npm run test:catalogue` и `UI_ORIGIN=http://127.0.0.1:8876 npm run check:catalogue:pages`. Проверяются переходы внутри и между серверными порциями, сохранение темы/поиска, старые якоря, история, отсутствие двойных целей и работа без JavaScript.
